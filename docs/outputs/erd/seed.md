# 임원 일정 관리 시스템 - 시드 데이터

본 문서는 운영 진입에 필수인 시드 데이터(공휴일, 관리자)와 개발/테스트 환경 검증용 시드를 SQL `INSERT` 문 형태로 정의한다. 모든 INSERT는 `erd.md`의 데이터 모델 및 제약조건을 준수한다.

## 작성 규칙

- UUID는 가독성을 위해 `'00000000-0000-0000-0000-0000000000XX'` 형태의 결정론적 값을 사용 (실제 마이그레이션은 `gen_random_uuid()` 또는 사전 정의 UUID 사용 가능)
- 비밀번호 해시는 Supabase Auth가 별도 관리하므로 본 문서의 INSERT에는 포함하지 않으며, 별도 admin 계정 생성 절차를 시드 적용 전에 수행한다고 가정
- 타임스탬프는 `now()` 사용 (마이그레이션 실행 시각으로 통일)

## 3. 시드 데이터 적용 순서 (의존성)

참조 무결성 위반 없이 실행해야 하는 INSERT 순서는 다음과 같다.

| 순서 | 테이블 | 의존성 / 사유 |
|:---:|--------|---------------|
| 1 | `users` | 모든 FK의 종착지. 관리자 계정 → 임원 → 비서 순서로 INSERT. |
| 2 | `companies` | `created_by` → `users.id` 참조. |
| 3 | `contacts` | `company_id` → `companies.id`, `created_by` → `users.id` 참조. |
| 4 | `proxy_permissions` | `proxy_user_id`, `target_user_id`, `granted_by` → `users.id` 참조. |
| 5 | `schedules` | `owner_id`, `created_by`, `on_behalf_of_id` → `users.id` 참조. |
| 6 | `mentions` | `schedule_id` → `schedules.id`, `reference_id` → `contacts/companies.id` 참조 (다형성). |
| 7 | `schedule_participants` | `schedule_id` → `schedules.id`, `user_id`, `added_by` → `users.id` 참조. |
| 8 | `holidays` | FK 의존성 없음. 단, `created_by`는 NULL 또는 관리자. 어느 시점에 넣어도 무방하나 마지막에 일괄 INSERT 권장. |

> `audit_logs`와 `notification_logs`는 시드로 직접 채우지 않는다. 운영 중 트리거로 자연 발생.

### 3-1. 트랜잭션 권장 패턴

```sql
BEGIN;
  -- 1. users
  -- 2. companies
  -- 3. contacts
  -- 4. proxy_permissions
  -- 5. schedules
  -- 6. mentions
  -- 7. schedule_participants
  -- 8. holidays
COMMIT;
```

운영 환경에서는 위 순서를 단일 트랜잭션으로 묶어 실행하면 중간 실패 시 자동 롤백된다.

## 4. 시드 데이터 정리 정책

### 4-1. 운영 환경 진입 전 개발 시드 제거 절차

> 개발/테스트 시드는 식별이 명확하도록 ID 패턴을 사용했다 (`...-0000-0000000000XX` 형태로 prefix 분리).

```sql
-- 운영 환경 cutover 직전 실행 (반드시 백업 후 실행)
BEGIN;

  -- 1. 의존성 역순으로 삭제
  DELETE FROM mentions               WHERE schedule_id IN (SELECT id FROM schedules WHERE id::text LIKE '00000000-0000-0000-0000-0000000040%');
  DELETE FROM schedule_participants  WHERE schedule_id IN (SELECT id FROM schedules WHERE id::text LIKE '00000000-0000-0000-0000-0000000041%')
                                        OR schedule_id IN (SELECT id FROM schedules WHERE id::text LIKE '00000000-0000-0000-0000-0000000040%');
  DELETE FROM schedules              WHERE id::text LIKE '00000000-0000-0000-0000-0000000040%'
                                        OR id::text LIKE '00000000-0000-0000-0000-0000000041%';
  DELETE FROM proxy_permissions      WHERE id::text LIKE '00000000-0000-0000-0000-0000000030%';
  DELETE FROM contacts               WHERE id::text LIKE '00000000-0000-0000-0000-0000000020%';
  DELETE FROM companies              WHERE id::text LIKE '00000000-0000-0000-0000-0000000010%';
  DELETE FROM users                  WHERE id::text LIKE '00000000-0000-0000-0000-0000000001%'
                                        OR id::text LIKE '00000000-0000-0000-0000-0000000002%';

  -- 2. 운영 시드(공휴일·관리자)는 유지 확인
  -- SELECT COUNT(*) FROM holidays WHERE year = 2026;  -- 19건 (법정 14 + 대체 5)
  -- SELECT * FROM users WHERE email = 'admin@company.local';  -- 1건

COMMIT;
```

### 4-2. 운영 시드(공휴일·관리자) 유지 정책

| 항목 | 정책 |
|------|------|
| 관리자 계정 (`admin@company.local`) | **삭제 금지**. 비밀번호는 운영 진입 직후 환경변수 기반의 강력한 값으로 강제 변경. 사용 후 추가 관리자가 등록되면 본 계정은 비활성화(`status='inactive'`)할 수 있다. |
| 2026년 공휴일 | 유지. HOL-001 배치가 매년 1월 1일 00:01 자동 갱신. 본 시드의 `is_active=true`는 변경하지 않는다. |
| 매년 갱신 | HOL-001 배치가 차년도 공휴일을 12월 중 사전 등록한다. 본 시드는 최초 1회용 + 운영 fallback 용도. |
| 공휴일 데이터 변경 시 | 임시 공휴일은 관리자가 HOL-002로 추가, HOL-003으로 삭제. 법정/대체 공휴일은 본 시드 또는 HOL-001 배치만 변경 가능. |
| 운영 시드 삭제 정책 | 어떤 경우에도 운영 시드를 자동화된 절차로 삭제하지 않는다. 수동 검증 후에만 삭제 가능. |
