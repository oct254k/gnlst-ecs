# 12. 이력 관리 (Audit Log)

**관련 프로세스**: [process/proc_09_audit_log.md](../process/proc_09_audit_log.md)

일정의 등록·수정 이력을 자동으로 저장하고, 누가 언제 무엇을 바꿨는지 추적한다. 대리 입력의 경우 실제 입력자와 명의 임원을 분리하여 기록한다.

---

## 이력 데이터 모델

### `audit_logs` 테이블

| 필드명 | 타입 | Null | 설명 |
|--------|------|------|------|
| `id` | 식별자 | NOT NULL | PK (자동 생성) |
| `schedule_id` | 식별자 | NOT NULL | 대상 일정 ID |
| `action` | 코드 | NOT NULL | `'created'`, `'updated'`, `'deleted'` (ERD `audit_logs.action` enum) |
| `actor_id` | 식별자 | NOT NULL | 실제 작업 수행 사용자 ID |
| `actor_name_snapshot` | 문자열 | NOT NULL | 실제 작업자 이름 (이름 변경 대비 스냅샷) |
| `on_behalf_of_id` | 식별자 | NULL | 대리 입력 시 명의 임원 ID (직접 입력 시 NULL) |
| `on_behalf_of_name_snapshot` | 문자열 | NULL | 대리 입력 시 명의 임원 이름 (스냅샷) |
| `before_data` | 객체 | NULL | 수정 전 값 (등록 시 NULL) |
| `after_data` | 객체 | NULL | 수정 후 값 (삭제 시 NULL) |
| `changed_fields` | 목록 | NULL | 변경된 필드명 배열 (수정 시) |
| `created_at` | 일시 | NOT NULL | 이력 생성 시각 |
| `ip_address` | 문자열 | NULL | 작업자 IP (선택적 수집) |

### 변경 전/후 값 예시

```json
// 수정 전 (before_data)
{
  "title": "삼성전자 미팅",
  "start_at": "2026-05-10T10:00:00+09:00",
  "end_at": "2026-05-10T11:00:00+09:00",
  "location": "본사 회의실 A"
}

// 수정 후 (after_data)
{
  "title": "삼성전자 미팅",
  "start_at": "2026-05-10T14:00:00+09:00",
  "end_at": "2026-05-10T15:00:00+09:00",
  "location": "본사 회의실 B"
}
```

## AUD-001: 일정 등록 이력 저장

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUD-001 |
| **기능명** | 일정 등록 이력 저장 |
| **버전** | 1.0 |

### 설명

일정이 등록될 때 이력 테이블에 이력 레코드를 자동 생성한다. 수정 전 값은 없음(NULL), 수정 후 값에는 등록된 일정의 전체 값을 저장한다.

### 사전 조건

- 일정 등록 완료
- 현재 세션에서 실제 작업자 식별 가능

### 입력값

| 필드 | 타입 | 설명 |
|------|------|------|
| 일정 ID | 식별자 | 등록된 일정 ID |
| 실제 작업자 ID | 식별자 | 현재 입력 사용자 |
| 명의 임원 ID | 식별자 | 대리 입력 시만 설정 (직접 입력 시 없음) |
| 등록 일정 전체 값 | 객체 | 등록된 일정의 모든 필드 |

### 처리 흐름

1. 일정 등록이 완료된다
2. 이력 레코드가 생성된다
   - 행위: '등록'
   - 실제 작업자: 현재 로그인 사용자
   - 명의 임원: 대리 입력 시만 설정, 직접 입력 시 없음
   - 수정 전 값: 없음
   - 수정 후 값: 등록된 일정 전체 필드
   - 변경 항목: 없음 (등록에는 해당 없음)
3. 일정 등록과 이력 기록이 동일 트랜잭션으로 처리된다 (이력 기록 실패 시 일정 등록도 취소)

### 출력

- 이력 테이블에 '등록' 레코드 생성

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 이력 기록 실패 | 트랜잭션 취소 → 일정 등록 실패 처리 (무결성 보장) |
| 실제 작업자 미확인 | 등록 요청 자체를 거부 (인증 실패 처리) |

연계 기능: AUD-004 (이력 조회 UI)

## AUD-002: 일정 수정 이력 저장

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUD-002 |
| **기능명** | 일정 수정 이력 저장 (변경 전/후 값 저장) |
| **버전** | 1.0 |

### 설명

일정이 수정될 때 변경 전 값과 변경 후 값을 이력에 저장한다. 변경된 항목 목록으로 어떤 필드가 달라졌는지 명시한다.

### 사전 조건

- 수정 전 일정 데이터 조회 완료 (수정 실행 이전)
- 일정 수정 완료

### 입력값

| 필드 | 타입 | 설명 |
|------|------|------|
| 일정 ID | 식별자 | 수정된 일정 ID |
| 실제 작업자 ID | 식별자 | 수정한 사용자 |
| 명의 임원 ID | 식별자 | 대리 수정 시만 설정 |
| 수정 전 일정 값 | 객체 | 수정 이전 스냅샷 |
| 수정 후 일정 값 | 객체 | 수정 이후 값 |

### 처리 흐름

1. 수정 전 일정 데이터를 조회한다 (스냅샷)
2. 일정 수정을 실행한다
3. 수정 전후 값을 비교하여 변경된 항목 목록을 계산한다
4. 이력 레코드를 생성한다
   - 행위: '수정'
   - 수정 전 값: 수정 전 스냅샷
   - 수정 후 값: 수정 후 값
   - 변경된 항목: 변경된 필드명 배열
5. 일정 수정과 이력 기록이 동일 트랜잭션으로 처리된다

### 출력

- 이력 테이블에 '수정' 레코드 생성
- 수정 전 값, 수정 후 값, 변경 항목 모두 기록

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 변경 내용 없음 (동일 값으로 저장) | 변경 항목 빈 배열로 이력 저장 (취소하지 않음) |
| 스냅샷 조회 실패 | 수정 요청 중단, 오류 반환 |
| 이력 기록 실패 | 트랜잭션 취소 → 수정 실패 처리 |

연계 기능: AUD-004 (이력 조회 UI)

## AUD-003: 대리 입력 이력 구분 저장

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUD-003 |
| **기능명** | 대리 입력 이력 구분 저장 (실제 작성자 별도 필드) |
| **버전** | 1.0 |

### 설명

관리자·비서 등이 다른 임원 명의로 일정을 등록/수정하는 **대리 입력** 시, 실제 입력자와 명의 임원을 별도 항목으로 저장하여 책임 소재를 명확히 한다.

### 대리 입력 여부 판별 기준

```
실제 입력자 ≠ 일정의 명의 임원 → 대리 입력
```

### 사전 조건

- 입력자가 대리 입력 권한 보유
- 일정 등록/수정 폼에서 명의 임원 선택

### 입력값

| 필드 | 타입 | 설명 |
|------|------|------|
| 실제 입력자 ID | 식별자 | 실제로 입력한 사용자 |
| 실제 입력자 이름 | 문자열 | 실제 입력자 이름 |
| 명의 임원 ID | 식별자 | 일정이 귀속되는 임원 |
| 명의 임원 이름 | 문자열 | 명의 임원 이름 |

### 처리 흐름

1. 일정 등록/수정 폼이 제출된다
2. 현재 세션 사용자와 명의 임원이 다른 경우 대리 입력으로 판별한다
3. 이력 기록 시 추가 항목을 포함한다
   - 실제 입력자 ID 및 이름 (스냅샷)
   - 명의 임원 ID 및 이름 (스냅샷)
4. 이력 조회 시 대리 입력 여부에 따라 표시 방식을 구분한다

### 이력 표시 예시

| 구분 | 표시 텍스트 |
|------|------------|
| 직접 입력 | `홍길동 전무 · 2026-05-11 14:23` |
| 대리 입력 | `홍길동 전무 명의 (입력: 김비서 · 2026-05-11 14:23)` |

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 대리 입력 권한 없음 | 접근 거부 처리 |
| 존재하지 않는 명의 임원 | 유효성 검사 실패 처리 |

연계 기능: AUD-001 (등록 이력), AUD-002 (수정 이력), AUD-004 (이력 조회 UI)

## AUD-004: 이력 조회 UI

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUD-004 |
| **기능명** | 이력 조회 UI |
| **버전** | 1.0 |

### 설명

일정 상세 화면에서 해당 일정의 등록/수정 이력 전체를 타임라인 형태로 표시한다. 관리자는 전체 이력을, 일반 임원은 본인 일정의 이력만 조회 가능하다.

### 사전 조건

- 일정 상세 페이지 접근 상태
- 조회 대상 일정의 이력 레코드 존재

### 접근 권한

| 역할 | 조회 범위 |
|------|-----------|
| 관리자 | 전체 일정의 이력 조회 가능 |
| 임원 | 본인 명의 일정 이력만 조회 가능 |

### 입력값

| 필드 | 타입 | 설명 |
|------|------|------|
| 일정 ID | 식별자 | 조회할 일정 ID |

### 처리 흐름

1. 일정 상세 화면에서 "이력 보기" 탭 또는 섹션을 클릭한다
2. 해당 일정의 이력 레코드를 시간 오름차순으로 조회한다
3. 각 이력 항목을 타임라인으로 렌더링한다
   - 아이콘: 등록 → ✅, 수정 → ✏️
   - 작성자: 대리 입력 여부 포함하여 표시
   - 변경 항목: 변경된 필드 요약
4. 변경 항목 상세를 토글로 펼쳐 필드별 이전값/이후값을 표시한다

### 타임라인 항목 표시 형식

```
[ ✅ 등록 ]  2026-05-11 09:00  홍길동 전무 직접 입력
             제목: 삼성전자 미팅
             일시: 2026-05-11 14:00~15:00
             장소: 본사 회의실 A

[ ✏️ 수정 ]  2026-05-11 10:30  홍길동 전무 명의 (입력: 김비서)
             변경 항목: ▼ 펼치기
               ┌──────────────┬─────────────────┬─────────────────┐
               │ 필드         │ 수정 전          │ 수정 후         │
               ├──────────────┼─────────────────┼─────────────────┤
               │ 장소         │ 본사 회의실 A    │ 본사 회의실 B   │
               └──────────────┴─────────────────┴─────────────────┘
```

### 출력

- 타임라인 형태의 이력 목록
- 각 항목: 행위(등록/수정), 시각, 작성자(대리 입력 여부), 변경 필드 요약
- 변경 상세: 필드별 이전값/이후값 표

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 이력 0건 | "이력이 없습니다" 빈 상태 표시 |
| 권한 없는 일정 이력 조회 | 접근 거부, "접근 권한이 없습니다" 표시 |
| 변경 항목 빈 배열 | "변경 내용 없음 (동일 값으로 재저장)" 표시 |

연계 기능: AUD-001 (등록 이력), AUD-002 (수정 이력), AUD-003 (대리 입력)
