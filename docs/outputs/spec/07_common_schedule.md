# 기능명세서: 공통 일정 (Common Schedule)

**관련 프로세스**: [process/proc_03_schedule.md](../process/proc_03_schedule.md) (일정 도메인 일부)

---

## 개요 및 설계 원칙

공통 일정은 복수의 임원이 공유하는 일정으로, 등록 시 참석 임원 전원에게 알림이 발송된다.

### 핵심 설계 결정 사항

> **수락/거절 프로세스 없음**
> 공통 일정에 대한 참가 수락 또는 거절 기능은 제공하지 않는다.
> 임원은 알림을 수신한 후, 참가 의사가 있을 경우 본인이 직접 해당 일정의 참가자 목록에 이름을 추가한다.
> 거절 또는 불참 의사 표시 기능은 제공하지 않으며, 참가자 목록에 이름이 없으면 불참으로 간주한다.

---

## 참가자 추가 흐름 다이어그램

아래는 공통 일정 등록 후 참가자가 본인 이름을 추가하는 전체 흐름이다.

```
[등록자]
    │
    ▼
공통 일정 등록 (COM-001)
    │
    ├─ 참석 임원 선택 (초기 참가자: 등록자만 또는 지정 임원)
    │
    ▼
시스템: 참석 임원 전체에게 알림 발송
    │
    ▼
[알림 수신: 임원 A, 임원 B, 임원 C ...]
    │
    ├── 임원 A: 참가 의사 있음
    │       │
    │       ▼
    │   참가자 목록에 본인 이름 직접 추가 (COM-002)
    │       │
    │       ▼
    │   참가자 목록: [등록자, 임원A]
    │
    ├── 임원 B: 참가 의사 없음
    │       │
    │       ▼
    │   아무 행동 없음 (수락/거절 없음)
    │       │
    │       ▼
    │   참가자 목록에 포함되지 않음 = 불참
    │
    └── 임원 C: 나중에 결정
            │
            ▼
        참가자 추가는 일정 당일 이전까지 가능
```

## COM-001: 공통 일정 등록

| 항목 | 내용 |
|------|------|
| **기능 ID** | COM-001 |
| **기능명** | 공통 일정 등록 |
| **설명** | 복수 임원이 공유할 일정을 등록한다. 등록 완료 시 지정된 참석 임원 전원에게 알림이 자동 발송된다. |
| **사전조건** | - 사용자 로그인 상태<br>- 공통 일정 등록 권한 보유 (모든 임원 또는 관리자) |
| **입력값** | - 일정 내용 (필수, 최대 200자)<br>- 날짜 (필수)<br>- 시간대 (필수: 오전/오후/종일)<br>- 시작 시간 (선택, HH:mm)<br>- 종료 시간 (선택, HH:mm)<br>- 장소 (선택)<br>- 알림 발송 대상 임원 (필수, 1명 이상) |

### 처리 흐름

1. 공통 일정 등록 폼을 연다 (달력 뷰 또는 리스트 뷰에서 접근).
2. 일정 유형은 "공통"으로 고정된다.
3. 필드를 입력한다.
   - 일정 내용 (텍스트)
   - 날짜 (날짜 선택)
   - 시간대 드롭다운 (오전/오후/종일)
   - 실제 시간 (HH:mm~HH:mm 형식)
   - 장소·파트너 (텍스트, 선택)
   - 알림 발송 대상 임원: 전체 임원 다중 선택
     - "전체 선택" 버튼으로 일괄 선택 가능
4. 저장 버튼을 클릭한다.
5. 유효성 검사를 수행한다.
   - 필수 필드 확인
   - 시작 시간 < 종료 시간 확인
   - 알림 발송 대상 1명 이상 확인
6. 유효성 통과 시 일정을 저장한다.
7. 저장 성공 시:
   - 알림 발송 대상 전원에게 실시간 알림을 발송한다.
   - 달력/리스트에 공통 일정이 즉시 반영된다.
   - 등록자는 초기 참가자에 자동 추가된다 (선택).
   - 성공 토스트를 표시한다: "공통 일정이 등록되었습니다. {n}명에게 알림이 발송되었습니다."
8. 저장 실패 시 오류 메시지를 표시하고 입력값을 유지한다.

### 알림 발송 규격

| 항목 | 내용 |
|------|------|
| 발송 시점 | 저장 완료 직후 |
| 수신 대상 | 알림 발송 대상 임원 전원 |
| 알림 채널 | 시스템 내 알림 벨, 이메일 (설정에 따라) |
| 알림 내용 | `"{등록자}님이 공통 일정을 등록했습니다: {일정 내용} ({날짜} {시간대})"` |
| 알림 링크 | 해당 공통 일정 상세 화면으로 이동 |

### 유효성 검사

| 필드 | 규칙 | 오류 메시지 |
|------|------|------------|
| 일정 내용 | 필수, 1~200자 | "일정 내용을 입력해주세요" |
| 날짜 | 필수, 유효한 날짜 | "날짜를 선택해주세요" |
| 시간대 | 필수 | "시간대를 선택해주세요" |
| 실제 시간 | 시작 < 종료 (입력 시) | "종료 시간이 시작 시간보다 앞서야 합니다" |
| 알림 대상 | 1명 이상 | "알림 발송 대상을 1명 이상 선택해주세요" |

| 출력 | 설명 |
|------|------|
| 달력/리스트 반영 | 공통 일정 색상으로 즉시 표시 |
| 알림 발송 | 대상 임원 전원에게 실시간 알림 |
| 성공 토스트 | 등록 완료 메시지 + 알림 발송 건수 |

### 예외 처리

| 상황 | 처리 |
|------|------|
| 알림 발송 일부 실패 | 일정 저장 유지, "일부 알림 발송 실패" 경고 토스트 |
| 전체 알림 발송 실패 | 일정 저장 유지, "알림 발송에 실패했습니다. 수동으로 공유해주세요" |
| 중복 일정 | 경고 토스트 표시 후 저장 허용 |

## 공통 일정 참가자 상태 정의

### 상태 목록

| 상태값 | 의미 |
|--------|------|
| `joined` | 해당 임원이 공통 일정에 참가 중인 상태 |
| `cancelled` | 참가 후 취소한 상태. 이력 보존을 위해 레코드를 물리 삭제하지 않음 |

> 수락/거절 프로세스는 제공하지 않는다. 참가 의사가 있는 임원이 직접 참가자 목록에 이름을 추가하며, 이것이 곧 참가 확정이다.

### 상태 전이 규칙

| From | To | 조건 | 처리 주체 |
|------|----|------|---------|
| (없음) | `joined` | 임원 본인이 공통 일정에 참가 추가 | 임원 본인 |
| `joined` | `cancelled` | 임원 본인이 참가 취소 | 임원 본인 |
| `cancelled` | `joined` | 임원 본인이 재참가 추가 | 임원 본인 |

### 참가자 이력 보존 항목

| 항목 | 설명 |
|------|------|
| 참가 일시 | 최초 참가를 추가한 일시 |
| 취소 일시 | 참가를 취소한 일시 (`cancelled_at`) |
| 상태 | 현재 참가 상태 (`joined` / `cancelled`) |

### 관리자 조작 정책

- 관리자는 공통 일정 자체를 등록/수정/삭제할 수 있으나, 참가자 목록은 임원 본인만 조작 가능하다
- 단, 관리자가 공통 일정을 삭제하면 해당 일정의 모든 참가자 레코드도 함께 논리 삭제된다

## COM-002: 공통 일정 참가자 자기 추가

| 항목 | 내용 |
|------|------|
| **기능 ID** | COM-002 |
| **기능명** | 공통 일정 참가자 자기 추가 |
| **설명** | 알림을 받은 임원이 해당 공통 일정에 참가 의사가 있을 경우, 본인 이름을 직접 참가자 목록에 추가한다. 수락/거절 프로세스는 없으며 추가만 가능하다. |
| **사전조건** | - 사용자 로그인 상태<br>- 해당 공통 일정이 존재<br>- 현재 로그인 사용자가 알림 발송 대상에 포함되어 있음 |
| **입력값** | - 공통 일정 식별자<br>- 현재 로그인 임원 정보 (자동) |

### 처리 흐름

1. 임원이 알림을 클릭하거나 달력/리스트에서 공통 일정을 클릭한다.
2. 공통 일정 상세 패널/모달이 열린다.
3. 상세 패널 구성:
   - 일정 정보 (제목, 날짜, 시간, 장소)
   - 참가자 목록: 현재 추가된 임원 목록
   - "참가하기" 버튼
4. 현재 로그인 임원이 이미 참가자 목록에 있으면:
   - "참가하기" 버튼 비활성화 또는 "참가 취소" 버튼 표시
5. "참가하기" 버튼을 클릭한다.
   - 시스템이 참가자 목록에 본인을 추가한다.
   - 성공 시: 참가자 목록 즉시 갱신, "참가자로 추가되었습니다" 토스트 표시
6. 참가 추가는 별도 알림 발송 없이 조용히 처리된다.

> **주의**: 수락/거절 프로세스가 없으므로 알림 발송 대상에 포함된 임원이라도 참가자 추가 행동을 하지 않으면 불참으로 간주된다. 시스템은 불참 여부를 별도로 관리하지 않는다.

### 참가자 목록 표시 형식

```
참가자 (2명 참가 중)
┌─────────────────────────────────────┐
│ ● 홍길동   추가: 2026-05-10 09:32  │
│ ● 김영희   추가: 2026-05-10 11:15  │
└─────────────────────────────────────┘
[+ 참가하기]
```

### 참가자 목록 렌더링 규칙

| 항목 | 규칙 |
|------|------|
| 헤더 카운터 | `참가자 (n명 참가 중)` — `schedule_participants`의 `status='joined'` 행 수 기준 |
| 목록 컨테이너 | `max-height: 320px; overflow-y: auto` — 참가자 10명 초과 시 내부 스크롤 |
| 스크롤바 | 목록 컨테이너 내부에만 적용 (모달/패널 전체 스크롤과 분리) |

### 참가 취소 정책

| 정책 | 내용 |
|------|------|
| 참가 취소 | 허용 (본인이 직접 추가한 이름은 본인이 취소 가능) |
| 취소 후 재추가 | 허용 |
| 타인 참가 추가 | 불허 (본인만 추가 가능) |
| 관리자 강제 추가/제거 | 허용 |

| 출력 | 설명 |
|------|------|
| 참가자 목록 갱신 | 실시간 업데이트 |
| 성공 토스트 | "참가자로 추가되었습니다" |

### 예외 처리

| 상황 | 처리 |
|------|------|
| 이미 참가자인 경우 중복 추가 | "이미 참가자 목록에 있습니다" 안내 |
| 일정 당일 이후 추가 시도 | 경고 없이 허용 (제한 없음, 추후 정책 결정 시 변경) |
| 알림 발송 대상이 아닌 사용자의 추가 시도 | "해당 일정의 참가 대상이 아닙니다" 안내 후 차단 |

## COM-003: 공통 일정 수정

| 항목 | 내용 |
|------|------|
| **기능 ID** | COM-003 |
| **기능명** | 공통 일정 수정 |
| **설명** | 등록된 공통 일정의 내용을 수정한다. 수정 완료 시 기존 알림 대상 임원 전원에게 변경 알림이 발송된다. |
| **사전조건** | - 사용자 로그인 상태<br>- 수정 권한: 등록자 본인 또는 관리자<br>- 해당 공통 일정 존재 |
| **입력값** | - 일정 식별자<br>- 수정할 필드값 (COM-001 입력값과 동일) |

### 처리 흐름

1. 공통 일정 상세에서 "수정" 버튼을 클릭한다 (권한자에게만 표시).
2. COM-001 등록 폼과 동일한 폼에 기존 데이터를 미리 채운다.
3. 수정 후 "저장"을 클릭한다.
4. 유효성 검사를 수행한다 (COM-001과 동일).
5. 일정을 저장한다.
6. 저장 성공 시:
   - 달력/리스트가 즉시 갱신된다.
   - 알림 발송 대상 전원에게 변경 알림이 발송된다.
     - 알림 내용: "{등록자}님이 공통 일정을 수정했습니다: {일정 내용}"
   - 참가자 목록은 유지된다 (수정해도 참가자는 초기화되지 않음).

### 수정 제한 사항

| 항목 | 내용 |
|------|------|
| 참가자 목록 | 수정 폼에서 직접 변경 불가 (참가자 추가/제거는 별도 기능) |
| 일정 유형 | 공통 ↔ 개인 전환 불가 |
| 변경 알림 | 수정 시 무조건 알림 재발송 (선택 불가) |

| 출력 | 설명 |
|------|------|
| 수정 반영 | 달력/리스트 즉시 갱신 |
| 변경 알림 | 알림 발송 대상 전원에게 발송 |

### 예외 처리

| 상황 | 처리 |
|------|------|

| 수정 중 타인 동시 수정 | 저장 시 충돌 감지, "최신 데이터를 확인해주세요" 경고 |

## COM-004: 공통 일정 삭제

| 항목 | 내용 |
|------|------|
| **기능 ID** | COM-004 |
| **기능명** | 공통 일정 삭제 |
| **설명** | 등록된 공통 일정을 삭제한다. 삭제 완료 시 기존 참가자 및 알림 대상 임원에게 취소 알림이 발송된다. |
| **사전조건** | - 사용자 로그인 상태<br>- 삭제 권한: 등록자 본인 또는 관리자<br>- 해당 공통 일정 존재 |
| **입력값** | - 삭제할 일정 식별자 |

### 처리 흐름

1. 공통 일정 상세에서 "삭제" 버튼을 클릭한다 (권한자에게만 표시).
2. 삭제 확인 모달을 표시한다.
   - "공통 일정 '{일정 내용}'을 삭제하시겠습니까? 참가자 {n}명에게 취소 알림이 발송됩니다."
   - [삭제] [취소]
3. "삭제" 확인 클릭 시 일정을 삭제한다 (논리 삭제: 삭제 여부 플래그 설정).
4. 삭제 성공 시:
   - 달력/리스트에서 해당 일정이 즉시 제거된다.
   - 알림 발송 대상 전원에게 취소 알림이 발송된다.
     - 알림 내용: "공통 일정이 취소되었습니다: {일정 내용} ({날짜})"
   - 성공 토스트를 표시한다: "공통 일정이 삭제되었습니다"

### 삭제 확인 모달 구성

```
┌─────────────────────────────────────────────────┐
│  공통 일정 삭제                                  │
│                                                  │
│  '임원 전체 워크숍'을 삭제하시겠습니까?          │
│  참가자 3명에게 취소 알림이 발송됩니다.          │
│                                                  │
│              [취소]  [삭제]                      │
└─────────────────────────────────────────────────┘
```

| 출력 | 설명 |
|------|------|
| 달력/리스트에서 제거 | 즉시 반영 |
| 취소 알림 | 알림 발송 대상 전원에게 발송 |
| 성공 토스트 | 삭제 완료 메시지 |

### 예외 처리

| 상황 | 처리 |
|------|------|
| 삭제 권한 없음 | "삭제 버튼" 미표시, 직접 요청 시 "권한이 없습니다" 안내 후 차단 |
| 이미 삭제된 일정 | "이미 삭제된 일정입니다" 안내 |
| 알림 발송 실패 | 삭제 완료 유지, 알림 실패 경고 토스트 |
