## 사용자 상태 정의

### 상태 목록

| 상태값 | 표시명 | 의미 |
|--------|--------|------|
| `pending` | 초대됨 | 초대 메일이 발송되었으나 비밀번호를 아직 설정하지 않은 상태 |
| `active` | 정상 | 비밀번호 설정 완료, 로그인 가능한 정상 계정 |
| `inactive` | 비활성 | 관리자에 의해 비활성화된 계정. 로그인 불가 |
| `locked` | 잠금 | 로그인 실패 횟수 초과로 일시 잠금된 계정. 일정 시간 후 자동 해제 |

### 상태 전이 규칙

| From | To | 조건 | 처리 주체 |
|------|----|------|---------|
| `pending` | `active` | 사용자가 초대 링크에서 비밀번호 설정 완료 | 시스템 자동 |
| `active` | `inactive` | 관리자가 사용자 관리 화면에서 비활성화 처리 | 관리자 |
| `inactive` | `active` | 관리자가 사용자 관리 화면에서 재활성화 처리 | 관리자 |
| `active` | `locked` | 로그인 5회 연속 실패 | 시스템 자동 |
| `locked` | `active` | 잠금 유지 시간(15분) 경과 후 자동 해제 | 시스템 자동 |

### 전이 불가 규칙

- `pending` 상태에서 `inactive` / `locked` 전이 불가 (아직 활성화된 계정이 아님)
- `locked` 상태에서 `inactive` 전이 불가 (잠금 해제 후 별도 비활성화 필요)
- 초대 링크는 발송 후 24시간이 경과하면 만료되며, 이 경우 상태는 `pending` 유지. 재초대 필요

### 상태별 허용 행위

| 상태 | 로그인 | 일정 조회 | 일정 등록/수정 | 관리자 기능 |
|------|:------:|:--------:|:------------:|:----------:|
| `pending` | ❌ | ❌ | ❌ | ❌ |
| `active` | ✅ | ✅ | ✅ (권한 범위 내) | 관리자 역할 보유 시 ✅ |
| `inactive` | ❌ | ❌ | ❌ | ❌ |
| `locked` | ❌ | ❌ | ❌ | ❌ |

## AUTH-001: 관리자 초대

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUTH-001 |
| **기능명** | 관리자 초대 |
| **Phase** | 1 |
| **설명** | 관리자가 신규 사용자를 이메일로 초대하면, 초대받은 사람이 메일 링크를 통해 비밀번호를 설정하고 계정을 활성화한다. |

### 사전 조건

- 요청자가 `ADMIN` 역할을 보유하고 있어야 한다.
- 초대할 이메일이 시스템에 등록되지 않은 주소여야 한다.

### 입력값

| 필드 | 타입 | 필수 | 유효성 규칙 |
|------|------|:---:|------------|
| 이메일 | string | ✅ | 이메일 형식, 중복 불허 |
| 이름 | string | ✅ | 1~50자 |
| 사번 | string | ✅ | 숫자 6~10자리, 중복 불허 |
| 역할 | enum | ✅ | `관리자` \| `일반` |

### 처리 흐름

1. 관리자가 초대 폼에 신규 사용자 정보(이메일, 이름, 사번, 역할)를 입력한다.
2. 시스템이 이메일 및 사번 중복 여부를 확인한다.
   - 중복 시 "이미 등록된 이메일(사번)입니다" 안내 후 중단한다.
3. 시스템이 초대 링크가 포함된 이메일을 발송한다.
   - 이메일 본문: 서비스명, 초대자 이름, 비밀번호 설정 링크
   - 링크 유효 시간: 24시간
4. 초대받은 사람이 메일 링크를 클릭한다.
5. 시스템이 초대 링크의 유효성을 검증한다.
   - 만료 시 "초대 링크가 만료되었습니다" 안내 후 재초대 요청 버튼을 표시한다.
6. 비밀번호 설정 폼이 표시된다.
   - 비밀번호: 최소 10자, 영문·숫자·특수문자 각 1자 이상 조합 (NFR-SEC-004 기준)
   - 비밀번호 확인 입력
7. 비밀번호 설정 완료 시 계정이 활성화되고, 자동 로그인 후 대시보드로 이동한다.

### 출력 / 결과

| 단계 | 결과 |
|------|------|
| 초대 발송 성공 | 관리자 화면에 "초대 메일이 발송되었습니다" 토스트 |
| 비밀번호 설정 완료 | 세션 생성, 대시보드로 이동 |

### 예외 처리

| 예외 상황 | 처리 방법 |
|----------|----------|
| 이메일 중복 | "이미 등록된 이메일입니다" 안내 |
| 사번 중복 | "이미 사용 중인 사번입니다" 안내 |
| 권한 없는 요청자 | "관리자만 초대할 수 있습니다" 안내 후 차단 |
| 초대 토큰 만료 (24h 초과) | 만료 안내 페이지, 관리자에게 재초대 요청 유도 |
| 비밀번호 정책 위반 | 폼 인라인 에러, 저장 차단 |
| 초대 이메일 발송 실패 | 메일 발송 실패 안내 표시, 처리 이전 상태로 롤백 |

## AUTH-002: 로그인

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUTH-002 |
| **기능명** | 로그인 |
| **Phase** | 1 |
| **설명** | 사용자는 이메일+비밀번호 또는 사번+비밀번호 두 가지 방식으로 로그인할 수 있다. 소셜 로그인은 제공하지 않는다. |

### 사전 조건

- 관리자 초대를 통해 계정이 활성화된 상태여야 한다.
- 브라우저 쿠키가 활성화되어 있어야 한다.

### 입력값

**방식 A — 이메일 + 비밀번호**

| 필드 | 타입 | 필수 | 유효성 규칙 |
|------|------|:---:|------------|
| 이메일 | string | ✅ | 이메일 형식 |
| 비밀번호 | string | ✅ | 1자 이상 |

**방식 B — 사번 + 비밀번호**

| 필드 | 타입 | 필수 | 유효성 규칙 |
|------|------|:---:|------------|
| 사번 | string | ✅ | 숫자 6~10자리 |
| 비밀번호 | string | ✅ | 1자 이상 |

### 처리 흐름

1. 사용자가 로그인 페이지에서 로그인 방식을 선택한다 ("이메일로 로그인" / "사번으로 로그인").
2. 인증 정보를 입력한다.
3. 시스템이 입력한 이메일(또는 사번)과 비밀번호를 검증한다.
   - 사번 로그인의 경우: 시스템이 사번으로 등록된 이메일을 조회한 뒤 인증을 수행한다.
4. 인증 성공 시 세션을 생성하고 대시보드로 이동한다.
   - 미인증 상태에서 접근 시도한 화면이 있으면 해당 화면으로 이동한다.
5. 계정 상태를 확인한다.
   - 활성화되지 않은 계정인 경우 "계정 활성화가 필요합니다" 안내를 표시한다.

### 출력 / 결과

| 결과 | 처리 |
|------|------|
| 로그인 성공 | 세션 생성, 대시보드로 이동 |
| 최초 로그인 | 비밀번호 변경 권고 배너 표시 (선택 사항) |

### 예외 처리

| 예외 상황 | 처리 방법 |
|----------|----------|
| 이메일/사번 없음 | "등록되지 않은 계정입니다" |
| 비밀번호 불일치 | "이메일(사번) 또는 비밀번호가 올바르지 않습니다" (계정 정보 노출 방지) |
| 계정 비활성화 | "비활성화된 계정입니다. 관리자에게 문의하세요" |
| 5회 연속 실패 | 계정 잠금 15분 + 안내 메시지 |
| 네트워크 오류 | "잠시 후 다시 시도해 주세요" |

## AUTH-003: 비밀번호 찾기

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUTH-003 |
| **기능명** | 비밀번호 찾기 |
| **Phase** | 1 |
| **설명** | 비밀번호를 잊은 사용자가 등록된 이메일로 재설정 링크를 받아 비밀번호를 변경한다. |

### 사전 조건

- 계정이 존재하고 이메일이 시스템에 등록된 상태여야 한다.
- 사용자가 로그아웃 상태여야 한다.

### 입력값

**1단계 — 이메일 입력**

| 필드 | 타입 | 필수 | 유효성 규칙 |
|------|------|:---:|------------|
| 이메일 | string | ✅ | 이메일 형식 |

**2단계 — 새 비밀번호 설정**

| 필드 | 타입 | 필수 | 유효성 규칙 |
|------|------|:---:|------------|
| 새 비밀번호 | string | ✅ | 최소 10자, 영문·숫자·특수문자 각 1자 이상 포함 (NFR-SEC-004 기준) |
| 비밀번호 확인 | string | ✅ | 새 비밀번호와 동일 |

### 처리 흐름

1. 사용자가 로그인 페이지에서 "비밀번호 찾기" 링크를 클릭한다.
2. 이메일을 입력하고 [재설정 링크 보내기]를 클릭한다.
3. 시스템이 해당 이메일로 비밀번호 재설정 링크를 발송한다.
   - 이메일이 등록되어 있지 않더라도 동일한 안내 화면을 표시한다 (계정 존재 여부 노출 방지).
   - 링크 유효 시간: 1시간
4. "메일을 확인하세요" 안내 화면이 표시된다.
5. 사용자가 메일 링크를 클릭한다.
6. 시스템이 링크의 유효성을 검증한다.
   - 만료 또는 무효 시 "링크가 만료되었습니다" 안내 후 재요청을 유도한다.
7. 새 비밀번호 입력 폼이 표시된다.
8. 비밀번호 변경 완료 후 로그인 페이지로 이동한다.
   - "비밀번호가 변경되었습니다. 다시 로그인해 주세요" 토스트 표시

### 출력 / 결과

| 단계 | 결과 |
|------|------|
| 이메일 제출 | "메일을 확인하세요" 안내 화면 (계정 존재 여부 무관하게 동일) |
| 비밀번호 변경 완료 | 로그인 페이지로 이동, 성공 토스트 |

### 예외 처리

| 예외 상황 | 처리 방법 |
|----------|----------|
| 미등록 이메일 | 동일한 "메일을 확인하세요" 응답 (보안) |
| 재설정 링크 만료 (1h 초과) | "링크가 만료되었습니다. 비밀번호 찾기를 다시 시도해 주세요" |
| 새 비밀번호 정책 위반 | 인라인 에러 메시지 |
| 새 비밀번호 불일치 | "비밀번호가 일치하지 않습니다" |
| 링크 재사용 시도 | "이미 사용된 링크입니다" |
| 이메일 발송 실패 | "메일 발송 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요" |

## AUTH-004: 세션 관리

| 항목 | 내용 |
|------|------|
| **기능 ID** | AUTH-004 |
| **기능명** | 세션 관리 |
| **Phase** | 1 |
| **설명** | 로그인 세션을 관리한다. 세션 자동 갱신, 만료 처리, 로그아웃을 포함한다. |

### 사전 조건

- 사용자가 로그인 완료 상태여야 한다.
- 모든 요청에 대해 세션 유효성이 자동으로 검증된다.

### 세션 정책

| 항목 | 값 |
|------|-----|
| 인증 토큰(JWT) 유효 시간 | 8시간 (NFR-SEC-005 기준) |
| 갱신 토큰(refresh) 유효 시간 | 30일 (NFR-SEC-005 기준) |
| 자동 갱신 | 인증 토큰 만료 전 자동으로 갱신 |

### 처리 흐름

1. 모든 페이지 요청 시 세션 유효성을 자동으로 검증한다.
2. 세션 상태에 따라 처리한다.
   - 유효한 세션: 요청 정상 처리, 필요 시 토큰 자동 갱신
   - 갱신 가능한 만료 세션: 갱신 토큰으로 새 인증 토큰을 발급하고 요청을 처리한다.
   - 완전히 만료된 세션: 로그인 페이지로 이동 (원래 접근하려던 화면 경로 보존)
3. 로그인이 필요한 화면 접근 시 세션이 없으면 로그인 페이지로 이동한다.
4. 로그인 화면 접근 시 세션이 있으면 대시보드로 이동한다.
5. 사용자가 로그아웃 버튼을 클릭하면 세션이 삭제되고 로그인 페이지로 이동한다.

### 로그인 없이 접근 가능한 화면

- 로그인 화면
- 비밀번호 찾기 화면
- 비밀번호 재설정 화면
- 초대 수락 화면

### 로그인 필수 화면

- 대시보드
- 일정 관련 모든 화면
- 관리자 화면
- 연락처 화면
- 엑셀 다운로드 화면

### 출력 / 결과

| 상황 | 결과 |
|------|------|
| 유효한 세션 | 요청 정상 처리 |
| 세션 자동 갱신 성공 | 새 인증 토큰 발급 후 투명하게 처리 |
| 세션 완전 만료 | 로그인 페이지로 이동 |
| 로그아웃 | 세션 삭제, 로그인 페이지로 이동 |

### 예외 처리

| 예외 상황 | 처리 방법 |
|----------|----------|
| 갱신 토큰 만료 | 세션 무효화 후 로그인 페이지로 이동, "보안을 위해 다시 로그인해 주세요" 토스트 |
| 다른 기기에서 비밀번호 변경 | 기존 세션 무효화, 재로그인 요구 |
| 쿠키 미지원 환경 | "쿠키를 활성화해야 로그인할 수 있습니다" 안내 |
| 관리자 계정 비활성화 | 다음 요청 시 자동 세션 해제 |
