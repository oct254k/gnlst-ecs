# 13. 내보내기 및 반응형 (Export & Responsive)

**관련 프로세스**: [process/proc_10_export.md](../process/proc_10_export.md)

현재 필터 상태 그대로 엑셀로 내보내는 기능과, 모바일 우선 설계의 반응형 레이아웃 명세.

> **Phase 결정 요약**: EXP-002 (Google Calendar 연동)는 **2차(Phase 2 이후) 진행 예정**이며 1차 범위에서 제외된다. 본 문서의 EXP-002 섹션 명세는 2차 작업 대상으로 보존한다.

## EXP-001: 엑셀 다운로드

| 항목 | 내용 |
|------|------|
| **기능 ID** | EXP-001 |
| **기능명** | 엑셀 다운로드 (현재 필터 상태 그대로) |
| **버전** | 1.0 |

### 설명

일정 목록 화면에서 현재 적용된 필터(임원, 날짜 범위, 일정 유형 등)를 유지한 채로 표시 중인 데이터를 `.xlsx` 파일로 다운로드한다. 서버 요청 없이 브라우저에서 직접 생성하여 전달한다.

### 사전 조건

- 일정 목록이 화면에 표시된 상태
- 현재 필터 상태가 유지 중

### 입력값

| 필드 | 타입 | 설명 |
|------|------|------|
| 필터 적용된 일정 목록 | 일정 배열 | 현재 필터 적용된 일정 |
| 필터 요약 레이블 | 문자열 | 파일명에 포함할 필터 요약 (예: `홍길동_2026-05`) |

### 다운로드 컬럼 구성

| 순서 | 열 헤더 | 데이터 필드 | 포맷 |
|------|---------|------------|------|
| 1 | 날짜 | 시작 일시 | `YYYY-MM-DD` |
| 2 | 시작 시각 | 시작 일시 | `HH:mm` |
| 3 | 종료 시각 | 종료 일시 | `HH:mm` |
| 4 | 일정 구분 | 일정 유형 | 공통 / 개인 |
| 5 | 제목 | 제목 | 텍스트 |
| 6 | 담당 임원 | 담당 임원 이름 | 텍스트 |
| 7 | 장소 | 장소 | 텍스트 (없으면 빈칸) |
| 8 | 회사 | 회사명 | 텍스트 |
| 9 | 담당자 | 담당자 이름 | 텍스트 |
| 10 | 메모 | 메모 | 텍스트 |
| 11 | 등록자 | 등록자 이름 | 텍스트 |
| 12 | 등록 일시 | 등록 일시 | `YYYY-MM-DD HH:mm` |

### 처리 흐름

1. "엑셀 다운로드" 버튼을 클릭한다 (추가 서버 요청 없이 현재 목록 사용)
2. 현재 일정 목록 데이터를 컬럼 구성에 맞게 변환한다 (날짜/시각 포맷 적용, 일정 유형 한글 변환)
3. 엑셀 워크시트를 생성하고 데이터를 채운다
4. 열 너비를 각 열의 최대 내용 길이에 맞게 설정한다
5. 엑셀 파일이 생성되어 브라우저 다운로드로 전달된다

### 출력

- 파일명: `일정_{filterLabel}_{YYYYMMDD}.xlsx`
- 예시: `일정_홍길동_20260511.xlsx`
- 브라우저 기본 다운로드 동작 (별도 서버 요청 없음)

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 필터된 데이터 0건 | 버튼 비활성화 또는 클릭 시 "다운로드할 데이터가 없습니다" 안내 |
| 데이터 1,000건 초과 | 경고 안내: "데이터가 많아 생성에 시간이 걸릴 수 있습니다" |
| 파일 생성 실패 | 오류 메시지 표시 |
| 모바일 브라우저 다운로드 | 일부 브라우저에서 파일 저장 위치 안내 메시지 추가 |

## EXP-002: 구글 캘린더 연동 (2차 작업 대상)

> **결정 (Phase 결정)**: EXP-002 (Google Calendar 연동)는 **2차(Phase 2 이후) 진행 예정. 1차 범위에서 제외.**
> 본 섹션의 명세는 2차 착수 시점에 참조할 수 있도록 보존되며, 1차 배포 범위에서는 구현하지 않는다.

| 항목 | 내용 |
|------|------|
| **기능 ID** | EXP-002 |
| **기능명** | 구글 캘린더 연동 |
| **상태** | **2차 진행 예정 — 1차 범위 제외** |
| **버전** | 1.0 (사양 문서만 보존, 1차 구현 대상 아님) |

### 1차 범위 처리 방침

> **2차 진행 예정 — 1차 범위 제외.**
> 1차 배포에는 포함하지 않으며, 메뉴 항목은 비활성 상태로만 노출한다. 구현 일정은 2차 범위 확정 후 별도 산정한다.

### 1차 범위 제외 사유

- 임원별 개인 외부 계정 관리 복잡성 (계정 분리, 권한 관리, OAuth 토큰 수명 관리)
- 1차 요구사항 범위 외 (내부 일정 시스템 우선 안정화)
- 추가 구현 공수 (인증·동기화·충돌 해소 로직) 1차 일정에 부합하지 않음

### 2차 진행 시 검토 사항

| 항목 | 내용 |
|------|------|
| 연동 방향 | 시스템 → Google Calendar (단방향 또는 양방향, 2차 진행 시 결정) |
| 검토 시점 | 2차 범위 확정 시 (Phase 2 이후) |
| 인증 방식 | Google OAuth 2.0 (사용자별 계정 연결) — 2차 진행 시 상세 설계 |
| 동기화 정책 | 충돌 해소·삭제 전파·재시도 — 2차 진행 시 별도 정의 |

### UI 처리 (1차 배포)

- 내보내기 메뉴에 "Google 캘린더 동기화" 항목을 **비활성화** 상태로 표시
- 호버 툴팁: **"2차 진행 예정 — 1차 범위 제외"**
- 클릭 시 동작 없음 (메뉴 항목은 비활성, 안내 토스트 없음)

## RES-001: 모바일 반응형 레이아웃

| 항목 | 내용 |
|------|------|
| **기능 ID** | RES-001 |
| **기능명** | 모바일 반응형 레이아웃 |
| **버전** | 1.0 |
| **설계 원칙** | 모바일 우선 (Mobile First) |

### 설명

모바일 → 태블릿 → 데스크탑 순서로 레이아웃이 확장되도록 설계한다.

### 반응형 구간 정의

| 구간 | 최소 너비 | 대상 디바이스 | 적용 레이아웃 |
|------|-----------|--------------|---------------|
| 기본 | 0px | 모바일 | 단일 컬럼, 전체 너비 |
| 소형 | 640px | 대형 폰 / 소형 태블릿 | 단일 컬럼 (여백 추가) |
| 중형 | 768px | 태블릿 | 2컬럼 그리드 시작 |
| 대형 | 1024px | 데스크탑 | 사이드바 + 메인 컨텐츠 |
| 특대형 | 1280px | 대형 데스크탑 | 사이드바 고정 + 넓은 메인 |
| 와이드 | 1536px | 와이드 모니터 | 최대 컨텐츠 너비 제한 |

### 화면별 레이아웃 전략

#### 일정 목록 화면

| 구간 | 레이아웃 |
|------|---------|
| 모바일 | 카드형 리스트 (1열), 필터는 상단 드롭다운 토글 |
| 태블릿 | 테이블 형태, 일부 컬럼 숨김 |
| 데스크탑 | 풀 테이블, 사이드 필터 패널 고정 표시 |

#### 모임 레이더 (슬롯 격자)

| 구간 | 레이아웃 |
|------|---------|
| 모바일 | 가로 스크롤 가능한 격자 테이블 |
| 데스크탑 | 화면 너비에 맞게 자동 확장 |

#### 관계 히스토리 카드

| 구간 | 레이아웃 |
|------|---------|
| 모바일 | 바텀 시트(Bottom Sheet, 화면 하단 슬라이드업) |
| 데스크탑 | 클릭 위치 기준 팝오버 |

#### 내비게이션

| 구간 | 레이아웃 |
|------|---------|
| 모바일 | 하단 탭바 (Tab Bar, 4~5개 항목) |
| 태블릿 | 상단 네비게이션 바 |
| 데스크탑 | 좌측 사이드바 (고정, 접기/펼치기 가능) |

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 가로 격자 스크롤 (레이더) | 가로 스크롤 가능 컨테이너로 처리 |
| 모달 전체 화면 (모바일) | 전체 화면 모달로 전환 |
| 팝오버 → 바텀 시트 전환 | 화면 너비 기준으로 표시 방식을 자동 전환 |

## RES-002: 모바일 입력 폼 UX

| 항목 | 내용 |
|------|------|
| **기능 ID** | RES-002 |
| **기능명** | 모바일 입력 폼 UX (탭/드롭다운 위주) |
| **버전** | 1.0 |

### 설명

모바일 환경에서 일정 등록/수정 폼의 입력 경험을 최적화한다. 자유 텍스트 입력을 최소화하고 탭·드롭다운·스위치 등 터치 친화적 컨트롤 위주로 설계한다.

### 입력 컨트롤 가이드라인

| 항목 | 데스크탑 | 모바일 |
|------|---------|--------|
| 일정 유형 (공통/개인) | 라디오 버튼 | 세그먼트 탭 (2-choice) |
| 담당 임원 선택 | 드롭다운 | 네이티브 선택 피커 (하단 피커) |
| 날짜 선택 | 날짜 선택기 (커스텀) | 네이티브 날짜 입력 |
| 시작/종료 시각 | 시각 선택기 (커스텀) | 네이티브 시각 입력 |
| 장소 | 텍스트 입력 | 텍스트 입력 (최근 장소 자동완성) |
| 메모 | 텍스트 영역 | 텍스트 영역 (최소화) |
| 종일 여부 | 체크박스 | 토글 스위치 |
| 저장 버튼 | 우측 상단 또는 폼 하단 | 화면 하단 고정 버튼 |

### 폼 구조 (모바일 단계별 입력)

```
[단계 없이 단일 스크롤 폼 — 필수 항목 상단 배치]

━━━━━━━━━━━━━━━━━━━━━
  [ 공통 ]  [ 개인 ]        ← 세그먼트 탭 (일정 유형)
━━━━━━━━━━━━━━━━━━━━━

  제목 *                    ← 텍스트 입력 (키보드 즉시 팝업)
  ┌─────────────────────┐
  │ 삼성전자 미팅        │
  └─────────────────────┘

  날짜 *      종일
  2026-05-11  ○────         ← 네이티브 날짜 입력 + 토글 스위치

  시작     종료
  14:00    15:00             ← 네이티브 시각 입력 (종일이면 숨김)

  담당 임원 *
  [ 홍길동 전무     ▼ ]     ← 네이티브 선택 피커

  장소
  [ 본사 회의실 A   ]       ← 텍스트 입력

  회사 / 담당자            (접기 가능 — 선택 입력)
  메모                     (접기 가능 — 선택 입력)

━━━━━━━━━━━━━━━━━━━━━
  [         저장하기        ]   ← 하단 고정 버튼
━━━━━━━━━━━━━━━━━━━━━
```

### 터치 인터랙션 규칙

| 항목 | 규칙 |
|------|------|
| 최소 탭 영역 | 44×44px (iOS HIG 기준) |
| 입력 폰트 크기 | 16px 이상 (자동 확대 방지) |
| 레이블 위치 | 입력 위쪽 (placeholder 대체 불가) |
| 오류 메시지 | 입력 바로 아래 빨간색 텍스트 |
| 키보드 가림 | 포커스 입력 항목 자동 스크롤 |

### 선택 입력 섹션 (접기/펼치기)

- 회사·담당자·메모 등 선택 입력 필드는 기본적으로 **접힌 상태**
- "추가 정보 입력 +" 버튼으로 펼치기
- 한 번 입력하면 자동으로 펼쳐진 상태 유지

### 예외 처리

| 예외 상황 | 처리 방법 |
|-----------|-----------|
| 필수 항목 미입력 후 저장 | 첫 번째 오류 필드로 자동 스크롤 + 인라인 오류 표시 |
| 종료 시각 < 시작 시각 | 즉시 인라인 오류: "종료 시각은 시작 시각 이후여야 합니다" |
| 네이티브 피커 미지원 브라우저 | 텍스트 입력으로 전환 + 기본 유효성 검사 |
| 저장 중 네트워크 오류 | 저장 버튼 비활성화 + 로딩 표시 → 실패 시 오류 메시지 |
