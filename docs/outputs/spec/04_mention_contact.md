## 연락처 상태 정의

### 상태 목록

| 상태값 | 의미 |
|--------|------|
| `auto` | @멘션 입력 중 처음 등장하여 시스템이 자동으로 등록한 미확인 연락처 |
| `confirmed` | 관리자가 내용을 검토·보완하여 확인 완료한 연락처 |
| `deleted` | 논리 삭제된 연락처. 기존 멘션 표시 유지를 위해 물리 삭제하지 않음 |

> 자동 등록(`auto`)된 연락처는 이름만 기록되며 소속 회사·직책 등이 미입력 상태일 수 있다.
> 관리자가 내용을 보완하는 순간 `confirmed` 상태로 전환된다.

### 상태 전이 규칙

| From | To | 조건 | 처리 주체 |
|------|----|------|---------|
| (없음) | `auto` | @멘션에서 검색 결과 없는 이름을 새 연락처로 등록 | 시스템 자동 |
| `auto` | `confirmed` | 관리자가 연락처 정보를 검토·보완 완료 | 관리자 |
| `confirmed` | `deleted` | 관리자가 연락처 삭제 처리 | 관리자 |
| `auto` | `deleted` | 관리자가 자동 등록된 연락처를 삭제 처리 | 관리자 |

### 전이 불가 규칙

- `confirmed → auto` 역전이 불가 (한 번 확인된 연락처는 미확인 상태로 되돌릴 수 없음)
- `deleted` 상태에서 복구 기능은 제공하지 않음

### 삭제된 연락처 처리 정책

- 연락처가 `deleted` 상태가 되어도 해당 연락처를 참조하는 기존 멘션은 유지된다
- 기존 멘션 표시: `[삭제된 연락처]`로 대체 표시 (연락처 상세 링크 비활성화)
- 신규 멘션 입력 시 삭제된 연락처는 자동완성 목록에 표시되지 않음

### 회사(Company) 상태

| 상태값 | 의미 |
|--------|------|
| `active` | 정상적으로 등록된 회사 |
| `deleted` | 논리 삭제된 회사 |

- 소속 연락처가 존재하는 회사는 삭제 불가. 연락처를 먼저 삭제하거나 소속 변경 후 삭제 가능

## MEN-001: @멘션 자동완성

| 항목 | 내용 |
|---|---|
| **기능 ID** | MEN-001 |
| **기능명** | @멘션 자동완성 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

일정 등록/수정 폼의 멘션 입력 필드에서 `@` 문자를 입력하면 실시간으로 자동완성 드롭다운이 표시된다. 개인 연락처 및 회사 양쪽을 통합 검색한다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 연락처 및 회사 데이터가 없어도 입력은 가능하며, 없는 항목은 MEN-002로 처리된다.

### 입력값

| 항목 | 설명 |
|---|---|
| 트리거 문자 | `@` |
| 검색어 | `@` 이후 입력된 텍스트 (공백 전까지) |
| 최소 검색 길이 | 0자 (트리거 직후 전체 목록 표시) |
| 최대 검색어 길이 | 50자 |

### 처리 흐름

1. 사용자가 멘션 입력 필드에 "@"를 입력한다.
2. 시스템이 "@" 입력을 감지하고 이후 입력되는 텍스트를 검색어로 수집한다.
3. 입력 잠시 멈춤 후 검색이 실행된다.
4. 시스템이 다음 순서로 검색한다.
   - 개인 연락처 이름 (부분 일치)
   - 회사명 (부분 일치)
   - 회사 별칭 (포함 여부)
   - 논리 삭제된 항목 제외
   - 최대 10건 반환 (개인 연락처 5건 + 회사 5건 우선)
5. 드롭다운에 결과를 표시한다.
   - 개인 연락처: [이름] · [소속 회사] · [직책]
   - 회사: [회사명] (별칭: [alias1, alias2])
6. 검색 결과가 없을 경우: "새로 등록: @[입력값]" 항목을 드롭다운 최하단에 표시한다.
7. 사용자가 항목을 클릭하거나 Enter 키를 누르면 선택 완료된다.
   - 선택된 항목은 인라인 칩(chip) 형태로 삽입된다.
   - 멘션 목록에 추가된다.
8. "새로 등록" 항목 선택 시 MEN-002 흐름으로 이동한다.
9. Escape 키 또는 입력 필드 외부 클릭 시 드롭다운이 닫힌다.

### 드롭다운 항목 UI 예시

```
┌─────────────────────────────────────────┐
│ 👤 홍길동  ·  삼성전자  ·  부장         │
│ 👤 홍길순  ·  LG전자    ·  과장         │
│ 🏢 삼성전자 (Samsung, 삼성)             │
│ ─────────────────────────────────────── │
│ + 새로 등록: @홍        (연락처/회사)   │
└─────────────────────────────────────────┘
```

### 출력

| 항목 | 내용 |
|---|---|
| 드롭다운 | 최대 10건 검색 결과 표시 |
| 선택 결과 | 인라인 칩 삽입, 멘션 목록 업데이트 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 검색 오류 | 드롭다운에 "검색 중 오류가 발생했습니다" 표시, 재시도 버튼 |
| 네트워크 지연 | 로딩 스피너 표시 (응답 지연 시) |
| 중복 선택 | 동일 항목 재선택 시 무시, 기존 칩 유지 |

## MEN-002: 새 연락처 자동 등록

| 항목 | 내용 |
|---|---|
| **기능 ID** | MEN-002 |
| **기능명** | 새 연락처 자동 등록 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

@멘션 자동완성 결과에 없는 이름/회사명을 사용자가 처음 입력하거나, "새로 등록" 항목을 선택할 경우 최소 정보(이름 또는 회사명)만으로 자동 등록을 수행한다. 자동 등록된 항목은 미확인 상태로 표시되며, 이후 관리자가 정보를 보완할 수 있다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 입력된 텍스트가 기존 연락처 또는 회사와 중복되지 않아야 한다.

### 중복 감지 로직

1. 이름 기준 중복 검사 (개인 연락처):
   - 기존 연락처 이름과 동일한 경우 (대소문자 무시, 공백 정규화)
   - 중복 시 기존 항목 ID 사용, 신규 등록 건너뜀
2. 회사명 기준 중복 검사 (회사):
   - 기존 회사명과 동일하거나 별칭 배열에 포함된 경우
   - 중복 시 기존 항목 ID 사용
3. 모두 해당 없으면 신규 등록 진행

### 처리 흐름

1. 사용자가 MEN-001 드롭다운에서 "새로 등록: @[입력값]"을 선택한다.
   (또는 일정 저장 시 멘션 목록에 미등록 텍스트가 포함된 경우)
2. 유형 선택 미니 다이얼로그가 표시된다.
   - "개인 연락처로 등록" / "회사로 등록" 선택
3. 선택에 따라 중복 감지 로직을 수행한다.
4. 중복이 없는 경우 시스템이 신규 항목을 등록한다.
   - 개인 연락처 선택 시: 이름만 저장, 소속·직책은 미확인 상태
   - 회사 선택 시: 회사명만 저장, 별칭은 빈 상태
5. 생성된 항목의 ID가 멘션 칩에 반영된다.
6. 관리자에게 "새로 등록된 연락처가 있습니다" 인앱 알림이 발송된다 (정보 보완 요청).
7. 자동 등록 항목은 일정 목록/상세 화면에서 "[이름] (미확인)" 배지로 표시된다.

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 생성된 개인 연락처 또는 회사 정보 |
| UI 반영 | 멘션 칩 업데이트, "(미확인)" 배지 표시 |
| 알림 | 관리자 인앱 알림 발송 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 중복 감지 | 기존 항목 재사용, 사용자에게 "기존 [이름]과 연결됩니다" 안내 |
| 입력값이 공백만 존재 | 등록 불가, "유효한 이름을 입력해주세요" |
| 저장 실패 | 일정 저장은 계속 진행, 멘션은 원본 텍스트만 저장 후 재처리 |

## CON-001: 연락처 등록 (관리자)

| 항목 | 내용 |
|---|---|
| **기능 ID** | CON-001 |
| **기능명** | 연락처 등록 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

관리자가 개인 연락처를 직접 등록한다. MEN-002로 자동 등록된 항목에 추가 정보를 보완하거나, 처음부터 완전한 정보로 신규 등록할 수 있다.

### 사전 조건

- 사용자가 관리자 역할이어야 한다.

### 입력값

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 이름 | string(50) | 필수 | 연락처 이름 |
| 소속 회사 | UUID | 선택 | 소속 회사 |
| 직책 | string(50) | 선택 | 직책 |
| 이메일 | string(100) | 선택 | 이메일 주소 |
| 전화번호 | string(20) | 선택 | 전화번호 |

### 처리 흐름

1. 관리자가 연락처 관리 페이지에서 "새 연락처" 버튼을 클릭한다.
2. 등록 폼에 정보를 입력한다.
3. 이름 필드 입력 시 실시간 중복 검사를 수행한다.
   - 동일한 이름이 존재하면 "이미 등록된 이름입니다. 기존 항목을 수정하시겠습니까?" 안내
4. 저장 버튼 클릭 시 유효성 검사를 수행한다.
   - 이름 필수, 1~50자
   - 이메일 형식 유효성 (입력된 경우)
5. 저장이 완료되면 연락처 목록에 즉시 반영된다.

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 생성된 연락처 정보 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 비관리자 접근 | "관리자만 등록할 수 있습니다" 안내 후 차단. 등록 버튼 미표시 |
| 이름 중복 | 경고 메시지 표시, 사용자 선택에 따라 계속 진행 또는 취소 |
| 유효성 오류 | 필드별 인라인 오류 표시 |

## CON-002: 연락처 수정 (관리자)

| 항목 | 내용 |
|---|---|
| **기능 ID** | CON-002 |
| **기능명** | 연락처 수정 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

관리자가 기존 연락처 정보를 수정한다. MEN-002로 자동 등록된 항목의 정보를 보완하는 주요 경로이기도 하다. 수정 완료 후 자동 등록 여부가 확인 완료 상태로 전환된다.

### 사전 조건

- 사용자가 관리자 역할이어야 한다.
- 수정 대상 연락처가 존재해야 한다.

### 입력값

CON-001 입력값과 동일 (모든 필드 선택적 수정 가능).

### 처리 흐름

1. 관리자가 연락처 목록에서 항목을 선택하고 "수정" 버튼을 클릭한다.
2. 기존 정보를 폼에 미리 채워서 수정 화면을 연다.
   - 자동 등록된 항목은 "(미확인 - 자동 등록)" 배지를 표시하여 식별
3. 관리자가 정보를 수정하고 저장 버튼을 클릭한다.
4. 변경된 필드만 저장된다.
   - 자동 등록 항목인 경우 수정 완료 시 자동으로 확인 완료 상태로 전환
5. 저장 완료 후 연락처 목록 및 관련 일정의 멘션 표시가 즉시 업데이트된다.
   - "(미확인)" 배지 제거

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 수정된 연락처 정보 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 비관리자 접근 | "관리자만 수정할 수 있습니다" 안내 후 차단 |
| 연락처 미존재 | "연락처를 찾을 수 없습니다" 안내 |

## CON-003: 연락처 삭제 (관리자)

| 항목 | 내용 |
|---|---|
| **기능 ID** | CON-003 |
| **기능명** | 연락처 삭제 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

관리자가 연락처를 삭제한다. 논리 삭제 방식을 사용하며, 삭제된 연락처를 멘션하고 있는 기존 일정에는 "[삭제된 연락처]"로 표시된다.

### 사전 조건

- 사용자가 관리자 역할이어야 한다.
- 삭제 대상 연락처가 존재해야 한다.

### 처리 흐름

1. 관리자가 연락처 항목에서 "삭제" 버튼을 클릭한다.
2. 확인 다이얼로그를 표시한다.
   - "[이름]을 삭제하면 해당 연락처를 멘션한 기존 일정에서 이름이 표시되지 않을 수 있습니다. 삭제하시겠습니까?"
3. 확인 클릭 시 시스템이 논리 삭제를 처리한다 (삭제 시각 기록).
4. 해당 연락처를 멘션하고 있는 기존 일정의 멘션 레코드는 유지되며, 조회 시 "[삭제된 연락처]"로 표시된다.

### 출력

| 항목 | 내용 |
|---|---|
| 처리 결과 | 논리 삭제 완료 (삭제 시각 기록) |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 비관리자 접근 | "관리자만 삭제할 수 있습니다" 안내 후 차단 |
| 이미 삭제된 항목 | "이미 삭제된 연락처입니다" 안내 |

## CON-004: 연락처 조회 (전체)

| 항목 | 내용 |
|---|---|
| **기능 ID** | CON-004 |
| **기능명** | 연락처 조회 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

로그인한 모든 사용자가 연락처 목록을 조회할 수 있다. 검색 및 필터링을 지원한다. 수정/삭제 버튼은 관리자에게만 표시된다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.

### 검색/필터 조건

| 항목 | 타입 | 설명 |
|---|---|---|
| 검색어 | string | 이름/소속/직책 통합 검색 |
| 소속 회사 | UUID | 특정 회사 소속 필터 |
| 미확인 항목만 | boolean | 자동 등록 후 보완되지 않은 항목만 조회 (관리자 전용) |
| 페이지 번호 | number | 페이지 번호 (기본값: 1) |
| 페이지당 항목 수 | number | 기본값: 20, 최대: 100 |

### 처리 흐름

1. 사용자가 연락처 관리 페이지에 접근한다.
2. 시스템이 유효한 항목(논리 삭제되지 않은 항목)만 조회한다.
3. 검색어 입력 시 이름, 직책, 소속 회사명을 대상으로 부분 일치 검색을 수행한다.
4. 결과를 테이블 형태로 표시한다.
   - 열: 이름 / 소속 회사 / 직책 / 등록 방식(수동/자동) / 등록일
   - 관리자: 수정 / 삭제 버튼 표시
   - 일반 사용자: 조회만 가능

### 출력

| 항목 | 내용 |
|---|---|
| 연락처 목록 | 유효한 연락처 목록 (페이지네이션 포함) |
| 전체 건수 | 조건에 맞는 전체 항목 수 |

## CON-005: 회사 관리 (회사명 + 별칭 alias)

| 항목 | 내용 |
|---|---|
| **기능 ID** | CON-005 |
| **기능명** | 회사 관리 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

관리자가 회사 정보를 등록·수정·삭제한다. 회사에는 공식 회사명 외에 복수의 별칭(alias)을 등록할 수 있으며, @멘션 자동완성에서 별칭으로도 검색 가능하다.

### 사전 조건

- 등록/수정/삭제는 관리자 역할이어야 한다.
- 조회는 로그인한 모든 사용자가 가능하다.

### 입력값 (등록/수정 공통)

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 회사명 | string(100) | 필수 | 공식 회사명 |
| 별칭 | string[] | 선택 | 별칭 배열 (예: `["삼성전자", "Samsung", "SEC"]`) |

### 별칭 동작 규칙

| 상황 | 동작 |
|---|---|
| @멘션 자동완성 | 회사명 및 별칭 모두 검색 대상 |
| 드롭다운 표시 | 회사명 메인 표시, 별칭은 소괄호 안에 나열 |
| 중복 감지 | 다른 회사의 회사명 또는 별칭과 중복 불허 |
| 자동 등록(MEN-002) | 회사명으로만 등록, 별칭은 빈 상태 |

### 처리 흐름

#### 등록

1. 관리자가 회사 관리 페이지에서 "새 회사" 버튼을 클릭한다.
2. 회사명과 별칭을 입력한다.
   - 별칭은 태그 입력 방식 (Enter 또는 쉼표로 구분)
3. 회사명 입력 시 기존 회사명 및 별칭과의 중복을 실시간으로 검사한다.
4. 저장 완료 후 회사 목록에 즉시 반영된다.

#### 수정

1. 관리자가 회사 항목에서 "수정" 버튼을 클릭한다.
2. 기존 회사명과 별칭을 폼에 미리 채워서 수정 화면을 연다.
3. 별칭 수정:
   - 기존 별칭 삭제: 칩(chip)의 X 버튼 클릭
   - 신규 별칭 추가: 태그 입력
   - 추가/삭제 시 다른 회사와 중복 여부를 실시간으로 검사한다.
4. 저장 완료 후 변경된 별칭이 @멘션 자동완성에 즉시 반영된다.

#### 삭제

1. 관리자가 회사 항목에서 "삭제" 버튼을 클릭한다.
2. 해당 회사를 소속으로 하는 연락처가 있을 경우 경고를 표시한다.
   - "이 회사를 소속으로 하는 연락처 N명이 있습니다. 삭제하면 소속 정보가 비워집니다."
3. 확인 클릭 시 시스템이 논리 삭제를 처리한다.
4. 해당 회사를 소속으로 하는 연락처의 소속 정보가 비워진다.

#### 조회

- 회사명 또는 별칭으로 검색 가능
- 테이블 열: 회사명 / 별칭 / 소속 연락처 수 / 등록 방식 / 등록일

### 출력 예시

| 회사명 | 별칭 | 소속 연락처 수 | 등록 방식 | 등록일 |
|--------|------|:-------------:|----------|--------|
| 삼성전자 | Samsung, SEC, 삼성 | 5 | 수동 | 2026-01-01 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 비관리자 수정/삭제 시도 | "관리자만 수정/삭제할 수 있습니다" 안내 후 차단 |
| 회사명 중복 | "이미 등록된 회사명입니다" 인라인 오류 |
| 별칭 중복 (타 회사) | "이미 다른 회사([회사명])의 별칭으로 등록되어 있습니다" 오류 |
| 소속 연락처 있는 회사 삭제 | 경고 다이얼로그 후 사용자 확인 시 진행 |
