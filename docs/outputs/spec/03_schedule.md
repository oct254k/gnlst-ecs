## 공통 참조

### 날짜 파싱 지원 형식

| 입력 예시 | 해석 결과 |
|---|---|
| `2026-05-11` | 2026년 5월 11일 |
| `5/11` | 당해 연도 5월 11일 |
| `05/11` | 당해 연도 5월 11일 |
| `내일` | 오늘 + 1일 |
| `모레` | 오늘 + 2일 |
| `다음주 월요일` | 다음 주 월요일 |
| `이번주 금요일` | 이번 주 금요일 |
| `5월 11일` | 당해 연도 5월 11일 |
| `11일` | 당월 11일 |

> 파싱 실패 시 입력 필드에 인라인 오류 표시, 저장 불가 처리.

### 시간대 자동 매핑

| 실제 시간 범위 | 매핑 시간대 | 표시 레이블 |
|---|---|---|
| 00:00 ~ 11:59 | 오전 | 오전 |
| 12:00 ~ 13:59 | 점심 | 점심 |
| 14:00 ~ 17:59 | 오후 | 오후 |
| 18:00 ~ 23:59 | 저녁 | 저녁 |
| 종일 (시간 미입력) | 전일 | 전일 |

> - 실제 시간 입력 시 시작 시간 기준으로 시간대 자동 선택.
> - 사용자가 시간대 드롭다운을 수동으로 변경하면 자동 매핑 결과를 덮어씀.
> - 종일 토글 선택 시 실제 시간 필드 비활성화, 시간대는 "전일"로 고정.

## 일정 상태 정의

### 상태 목록

| 상태값 | 의미 |
|--------|------|
| `active` | 정상적으로 등록된 일정. 달력·리스트 뷰에 표시됨 |
| `deleted` | 논리 삭제된 일정. 화면에 표시되지 않으나 이력 조회 가능 |

> 일정은 물리 삭제(DB 행 제거)를 사용하지 않고 논리 삭제(soft delete) 방식으로 관리한다.
> 논리 삭제된 일정은 `deleted_at` / `deleted_by` 필드로 식별한다.

### 상태 전이 규칙

| From | To | 조건 | 처리 주체 |
|------|----|------|---------|
| (없음) | `active` | 일정 등록 완료 | 임원 본인 또는 대리 입력자, 관리자 |
| `active` | `deleted` | 일정 삭제 처리 | 임원 본인(본인 일정만), 관리자(전체) |

### 전이 불가 규칙

- `deleted` 상태에서 `active`로 복구하는 기능은 제공하지 않는다
- 삭제된 일정은 이력 조회(감사 로그)를 통해서만 내용 확인 가능

### 논리 삭제 식별 필드

| 필드 | 설명 |
|------|------|
| `deleted_at` | 삭제 처리된 일시. NULL이면 `active` 상태 |
| `deleted_by` | 삭제를 처리한 사용자. 관리자 삭제 시 이력 구분용 |

### 일정 유형별 삭제 권한

| 일정 유형 | 일반 임원 | 관리자 |
|----------|:--------:|:------:|
| 개인 일정 (본인) | ✅ | ✅ |
| 개인 일정 (타인) | ❌ | ✅ |
| 공통 일정 | ❌ | ✅ |
| 공휴일 (법정) | ❌ | ❌ |
| 공휴일 (임시) | ❌ | ✅ |

## SCH-001: 일정 등록 (개인)

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-001 |
| **기능명** | 개인 일정 등록 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

특정 임원 1명에게 귀속되는 일정을 등록한다. 일정 작성자가 해당 임원 본인이거나 대리 입력 권한을 가진 사용자일 수 있다. 날짜는 자유 형식 텍스트로 입력받아 파싱하며, 실제 시간 입력 시 시간대를 자동으로 매핑한다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 일정 주인(임원)이 시스템에 등록된 사용자여야 한다.
- 대리 입력인 경우 작성자에게 해당 임원에 대한 대리 입력 권한이 부여되어 있어야 한다.

### 입력값

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 일정 주인 | UUID | 필수 | 일정 주인 임원 |
| 날짜 | string | 필수 | 자유 형식 날짜 문자열 |
| 시간대 | enum | 필수 | 오전 / 점심 / 오후 / 저녁 / 전일 |
| 시작 시간 | string | 선택 | 실제 시작 시간 (HH:mm) |
| 종료 시간 | string | 선택 | 실제 종료 시간 (HH:mm) |
| 일정 내용 | string | 필수 | 자유 텍스트, 최대 200자 |
| 장소 | string | 선택 | 자유 텍스트, 최대 100자 |
| 비고 | string | 선택 | 자유 텍스트, 최대 500자 |
| 멘션 | string[] | 선택 | @멘션된 연락처/회사 목록 |

### 처리 흐름

1. 사용자가 일정 등록 폼을 열고 일정 유형 = "개인"을 선택한다.
2. 일정 주인(임원)을 선택한다.
   - 본인 일정: 로그인 사용자 자동 설정
   - 대리 입력: 권한이 있는 임원 선택 (→ SCH-006 참조)
3. 날짜를 자유 형식으로 입력한다.
   - 다양한 입력 형식을 순서대로 해석을 시도한다.
   - 해석 성공 시 달력에 해당 날짜를 하이라이트 표시한다.
   - 해석 실패 시 인라인 오류 메시지를 표시하고 저장 버튼을 비활성화한다.
4. 시간을 입력한다.
   - 종일 토글이 ON인 경우: 시간대 = "전일", 시간 입력 필드 비활성화
   - 시작 시간 입력 시: 시간대 자동 매핑 표를 기준으로 시간대 자동 선택
   - 사용자가 시간대를 수동 변경하면 자동 매핑 결과를 덮어씀
5. 일정 내용, 장소, 비고를 입력한다.
6. @멘션을 입력한다 (→ MEN-001 참조).
7. 저장 버튼 클릭 시 유효성 검사를 수행한다.
   - 날짜 해석 결과 존재 여부
   - 일정 내용 길이 (1~200자)
   - 시작 시간 < 종료 시간 (둘 다 입력된 경우)
8. 시스템에 일정 저장을 요청한다.
9. 저장 성공 시:
   - 캘린더 뷰 해당 날짜에 일정 카드 즉시 반영
   - 성공 토스트 메시지 표시
10. 멘션에 처음 등장하는 연락처/회사가 있을 경우 자동 등록 처리 (→ MEN-002)

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 생성된 일정 정보 |
| UI 반영 | 캘린더에 일정 카드 추가 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 날짜 해석 실패 | "날짜 형식을 확인해주세요" 오류 표시, 저장 불가 |
| 일정 내용 미입력 | "일정 내용을 입력해주세요" 오류 표시 |
| 시작 시간 > 종료 시간 | "종료 시간은 시작 시간 이후여야 합니다" 오류 표시 |
| 대리 입력 권한 없음 | "해당 임원의 일정을 입력할 권한이 없습니다" 안내 후 차단 |
| 서버 오류 | 오류 토스트 표시, 낙관적 업데이트 롤백 |

## SCH-002: 일정 등록 (공통)

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-002 |
| **기능명** | 공통 일정 등록 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

복수의 임원이 함께하는 공통 일정을 등록한다. 참가자를 복수로 선택할 수 있으며, 등록 완료 후 참가자 전원에게 알림을 발송한다. 공휴일은 본 기능이 아닌 시스템 자동/수동 처리로 별도 관리한다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 참가자로 지정된 임원이 모두 시스템에 등록되어 있어야 한다.
- 작성자에게 공통 일정 등록 권한이 있어야 한다.

### 입력값

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 참가자 | UUID[] | 필수 | 참가 임원 목록 (1인 이상) |
| 날짜 | string | 필수 | 자유 형식 날짜 문자열 |
| 시간대 | enum | 필수 | 오전 / 점심 / 오후 / 저녁 / 전일 |
| 시작 시간 | string | 선택 | 실제 시작 시간 (HH:mm) |
| 종료 시간 | string | 선택 | 실제 종료 시간 (HH:mm) |
| 일정 내용 | string | 필수 | 최대 200자 |
| 장소 | string | 선택 | 최대 100자 |
| 비고 | string | 선택 | 최대 500자 |
| 멘션 | string[] | 선택 | @멘션 연락처/회사 목록 |

### 처리 흐름

1. 사용자가 일정 등록 폼에서 일정 유형 = "공통"을 선택한다.
2. 참가자 선택 화면에서 임원을 복수 선택한다.
   - 검색 입력 + 드롭다운 목록 형태
   - 선택된 임원은 칩(chip) 형태로 표시, 개별 제거 가능
   - 최소 1인 이상 선택 필수
3. 날짜, 시간, 내용을 입력한다 (SCH-001 3~6단계와 동일).
4. 저장 버튼 클릭 시 유효성 검사를 수행한다.
   - 참가자 1인 이상 선택 여부
   - 날짜 해석 결과 존재 여부
   - 일정 내용 길이 (1~200자)
5. 시스템에 일정 저장을 요청한다.
6. 저장 완료 후 참가자 각각의 캘린더에 일정이 연결된다.
7. 참가자 전원에게 인앱 알림이 발송된다.
   - 알림 내용: "[작성자명]님이 공통 일정을 등록했습니다: [일정 제목]"
8. 저장 성공 시:
   - 캘린더 뷰에 공통 일정 카드 즉시 반영
   - 성공 토스트 메시지 표시

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 생성된 공통 일정 정보 (참가자 포함) |
| 알림 | 참가자 전원 인앱 알림 발송 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 참가자 미선택 | "참가자를 1명 이상 선택해주세요" 오류 표시 |
| 참가자 중 미등록 사용자 | 해당 사용자 안내 후 저장 차단 |
| 알림 발송 실패 | 일정 저장은 성공 처리, 알림 실패는 별도 재시도 처리 |
| 날짜/시간 오류 | SCH-001과 동일 |

## SCH-003: 일정 수정

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-003 |
| **기능명** | 일정 수정 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

기존 일정의 내용을 수정한다. 수정 가능한 범위는 사용자 권한에 따라 달라지며, 모든 수정은 이력으로 저장된다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 수정 대상 일정이 존재해야 한다.
- 권한에 따른 수정 범위가 적용된다.

### 권한별 수정 범위

| 역할 | 수정 가능 일정 |
|---|---|
| 일반 사용자 | 본인이 작성한 일정 (소유자 또는 작성자 기준) |
| 관리자 | 시스템 내 모든 일정 |
| 대리 입력 권한 보유자 | 권한이 부여된 임원의 일정 |

### 입력값

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 일정 ID | UUID | 필수 | 수정할 일정 |
| 날짜 | string | 선택 | 변경할 날짜 |
| 시간대 | enum | 선택 | 변경할 시간대 |
| 시작 시간 | string | 선택 | 변경할 시작 시간 |
| 종료 시간 | string | 선택 | 변경할 종료 시간 |
| 일정 내용 | string | 선택 | 변경할 일정 내용 |
| 장소 | string | 선택 | 변경할 장소 |
| 비고 | string | 선택 | 변경할 비고 |
| 멘션 | string[] | 선택 | 변경할 @멘션 목록 |

### 처리 흐름

1. 사용자가 일정 카드의 "수정" 버튼을 클릭한다.
2. 시스템이 수정 권한을 검증한다.
   - 일반 사용자: 본인이 작성한 일정인지 확인
   - 대리 입력 권한 보유자: 해당 임원의 권한 보유 여부 확인
   - 관리자: 무조건 허용
   - 권한 없으면 "수정 권한이 없습니다" 안내 후 차단
3. 기존 일정 데이터를 폼에 미리 채워서 수정 화면을 연다.
4. 사용자가 변경할 필드를 수정한다.
5. 저장 버튼 클릭 시 변경된 필드만 추출하여 저장을 요청한다.
6. 시스템이 수정 이력을 기록한다.
   - 변경 전 값, 변경 후 값, 수정자, 수정 시각
7. 저장 성공 시 캘린더 뷰가 즉시 업데이트되고 성공 토스트가 표시된다.

### 출력

| 항목 | 내용 |
|---|---|
| 저장 결과 | 수정된 일정 정보 |
| 이력 | 수정 이력 레코드 생성 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 권한 없음 | "수정 권한이 없습니다" 안내. 수정 버튼은 권한 없는 사용자에게 미표시 |
| 일정 미존재 | "일정을 찾을 수 없습니다" 안내 |
| 동시 수정 충돌 | "다른 사용자가 수정 중입니다. 새로고침 후 재시도해주세요" |
| 날짜/시간 유효성 오류 | SCH-001과 동일 |

## SCH-004: 일정 삭제

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-004 |
| **기능명** | 일정 삭제 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

등록된 일정을 삭제한다. 삭제는 논리 삭제(soft delete) 방식을 기본으로 하며, 삭제 권한은 SCH-003의 수정 권한과 동일하게 적용된다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 삭제 대상 일정이 존재해야 한다.
- SCH-003과 동일한 권한 규칙 적용.

### 처리 흐름

1. 사용자가 일정 카드의 "삭제" 버튼을 클릭한다.
2. 확인 다이얼로그를 표시한다: "[일정 제목]을 삭제하시겠습니까?"
3. 사용자가 확인을 클릭하면 권한 검증 후 삭제를 요청한다.
4. 시스템이 논리 삭제를 처리한다 (삭제 시각 및 삭제자 기록).
5. 공통 일정인 경우: 참가자 전원의 캘린더에서 해당 일정 카드가 제거된다.
6. 저장 성공 시 캘린더 뷰에서 일정 카드가 제거되고 성공 토스트가 표시된다.

### 출력

| 항목 | 내용 |
|---|---|
| 처리 결과 | 논리 삭제 완료 (삭제 시각 및 삭제자 기록) |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 권한 없음 | "삭제 권한이 없습니다" 안내. 삭제 버튼 미표시 |
| 일정 미존재 | "일정을 찾을 수 없습니다" 안내 |
| 이미 삭제된 일정 | "이미 삭제된 일정입니다" 안내 |

## SCH-005: 일정 상세 조회

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-005 |
| **기능명** | 일정 상세 조회 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

특정 일정의 상세 정보를 조회한다. 캘린더 뷰에서 일정 카드를 클릭하거나 직접 URL로 접근할 때 표시된다.

### 사전 조건

- 사용자가 로그인 상태여야 한다.
- 조회 대상 일정이 존재하고, 논리 삭제되지 않아야 한다.
- 개인 일정의 경우 해당 임원 본인 또는 관리자/대리 입력 권한 보유자만 조회 가능.

### 처리 흐름

1. 사용자가 캘린더에서 일정 카드를 클릭한다.
2. 시스템이 조회 권한을 검증하고 일정 상세 정보를 가져온다.
3. 상세 패널(또는 모달)에 정보를 표시한다.
   - 날짜, 시간대, 실제 시간, 일정 내용, 장소, 비고
   - @멘션 목록: 연락처명/회사명 + 소속/직책
   - 수정 이력 (최근 변경 요약): 수정자, 수정 시각
   - 공통 일정인 경우: 참가자 목록

### 출력

| 필드 | 타입 | 설명 |
|---|---|---|
| 일정 ID | UUID | 일정 고유 식별자 |
| 일정 유형 | enum | 개인 / 공통 / 공휴일 |
| 일정 주인 | object | 임원 정보 (개인 일정) |
| 참가자 목록 | object[] | 참가자 목록 (공통 일정) |
| 날짜 | date | 일정 날짜 |
| 시간대 | enum | 오전 / 점심 / 오후 / 저녁 / 전일 |
| 시작 시간 | string | 실제 시작 시간 |
| 종료 시간 | string | 실제 종료 시간 |
| 일정 내용 | string | 일정 제목/내용 |
| 장소 | string | 장소 |
| 비고 | string | 비고 |
| 멘션 목록 | object[] | 연락처/회사 목록 |
| 작성자 | UUID | 실제 등록자 |
| 최종 수정 시각 | datetime | 마지막 수정 시각 |

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 조회 권한 없음 | "조회 권한이 없습니다" 안내 후 차단 |
| 일정 미존재 또는 삭제됨 | "일정을 찾을 수 없습니다" 안내 |

## SCH-006: 대리 입력 (권한 보유자)

| 항목 | 내용 |
|---|---|
| **기능 ID** | SCH-006 |
| **기능명** | 대리 입력 |
| **버전** | 1.0 |
| **최종 수정일** | 2026-05-11 |

### 설명

대리 입력 권한을 보유한 사용자(예: 비서, 어시스턴트)가 특정 임원을 대신하여 일정을 등록·수정·삭제한다. 이 경우 실제 작성자(대리 입력자)와 일정 주인(임원)이 분리되어 로그에 저장된다.

### 사전 조건

- 작성자가 로그인 상태여야 한다.
- 작성자에게 특정 임원에 대한 대리 입력 권한이 부여되어 있어야 한다.
- 권한은 관리자가 대리 입력 권한 관리 기능을 통해 부여한다.

### 대리 입력 권한 구조

| 필드 | 설명 |
|---|---|
| 대리 입력자 | 대리 입력을 수행하는 사용자 |
| 대상 임원 | 일정 주인 임원 |
| 권한 부여자 | 권한을 부여한 관리자 |
| 부여 일시 | 권한이 부여된 시각 |

### 처리 흐름

1. 대리 입력 권한 보유자가 일정 등록 폼을 연다.
2. 일정 주인 선택 드롭다운에서 권한이 있는 임원 목록이 자동 필터링되어 표시된다.
3. 일정 주인을 선택하면:
   - 시스템이 해당 임원에 대한 대리 권한을 재확인한다.
   - 권한이 없으면 선택 불가 처리한다.
4. 일정 내용을 입력한다 (SCH-001 또는 SCH-002 흐름과 동일).
5. 저장 시 데이터베이스에 다음과 같이 기록된다.
   - 일정 주인: 선택한 임원
   - 작성자: 로그인 사용자 (대리 입력자)
   - 대리 입력 여부: true
6. 수정 이력에도 동일하게 대리 입력자 정보가 기록된다.
7. 일정 상세 조회 시 "대리 입력" 배지와 실제 작성자명이 표시된다.

### 로그 저장 구조

| 필드 | 타입 | 설명 |
|---|---|---|
| 일정 ID | UUID | 대상 일정 |
| 일정 주인 | UUID | 일정 주인 임원 |
| 실제 작성자 | UUID | 대리 입력자 |
| 대리 입력 여부 | boolean | 대리 입력 여부 표시 |
| 작업 유형 | enum | 등록 / 수정 / 삭제 |
| 처리 시각 | datetime | 처리 시각 |

### 출력

- 일정 저장 결과 (SCH-001/002와 동일)
- 일정 상세 화면에 "대리 입력 by [작성자명]" 배지 표시

### 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 대리 권한 없음 | "해당 임원의 일정을 대리 입력할 권한이 없습니다" 안내 후 차단 |
| 권한 만료 또는 취소 | 저장 시점에 재확인하여 만료된 경우 "권한이 없습니다" 안내 후 차단 |
